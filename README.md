# Endpoint-aligned carotid ultrasound segmentation on CUBS

This repository is the release candidate for the code and split metadata accompanying
the manuscript *Overlap and carotid intima-media thickness measurement accuracy can
disagree: an endpoint-aligned evaluation on the Carotid Ultrasound Boundary Study*.

The study evaluates carotid intima-media complex segmentation with both overlap metrics
and the downstream carotid intima-media thickness (CIMT) error. It contains the proposed
BC-VMamba implementation, experiment notebooks, analysis scripts, the fixed patient-level
partitions used in the paper, and a machine-readable experiment index. Raw CUBS images,
annotations, trained weights, and per-image prediction arrays are not redistributed.

## Data

Download both public CUBS releases from Mendeley Data:

- Clinical CUBS release: <https://doi.org/10.17632/fpv535fss7.1>
- Technical CUBS release: <https://doi.org/10.17632/m7ndn58sv6.1>

Place the extracted releases under `external_data/cubs_clinical` and
`external_data/cubs_technical`, or set `CUBS_DATA_ROOT` to a directory containing those
two folders. See [DATA.md](DATA.md) for the expected layout and data-use notes.

## Repository contents

- `data/`: sanitized experiment index and prespecified patient-level splits.
- `models/`: proposed BC-VMamba implementation.
- `notebooks/`: dataset-index construction, measurement-aligned training, baselines,
  and source-withholding experiments.
- `analysis/`: no-GPU scripts used for statistical and robustness analyses.
- `guards/check_release.py`: standalone integrity and portability checks.
- `NUMBERS.md`: numerical provenance ledger used while preparing the manuscript.

## Environment

Create a Python environment and install the portable analysis dependencies:

```bash
python -m pip install -r requirements.txt
```

The training notebooks require a CUDA-compatible PyTorch installation and the
GPU-specific `mamba-ssm`/`causal-conv1d` stack. Their first setup cell installs and checks
the versions appropriate to the active Kaggle or Colab runtime. Because compatible wheels
depend on the CUDA and PyTorch versions, these packages are intentionally not pinned in
`requirements.txt`.

Useful environment variables are:

| Variable | Meaning |
| --- | --- |
| `CUBS_DATA_ROOT` | Parent of `cubs_clinical/` and `cubs_technical/`. |
| `CUBS_EXPERIMENT_ROOT` | Root containing analysis inputs and generated results. |
| `CUBS_RUNS_ROOT` | Root containing downloaded raw experiment outputs. |
| `CUBS_PROPOSED_RUN` | Proposed-model run directory for scripts that need it. |
| `CUBS_LOCO_RUN` | Downloaded source-withholding output directory. |
| `CUBS_BASELINE_LOG_DIR` | Baseline training-log directory. |

Each analysis script documents the specific CSV or log inputs it expects. These inputs are
generated by the notebooks but are not included when they contain large prediction arrays
or derived participant-level records.

## Reproduction outline

1. Download both CUBS releases and configure `CUBS_DATA_ROOT`.
2. Run `python notebooks/E0_build_dataset_index.py` and compare its generated index and
   partitions with the committed files in `data/`.
3. Run `notebooks/E1_measurement_aligned_training.ipynb` for the proposed model and
   measurement-aligned ablation.
4. Run `notebooks/E2_baselines.ipynb` for architecture baselines.
5. Run `notebooks/E3_source_withholding.ipynb` for source-withholding experiments.
6. Point the environment variables above to the downloaded outputs, then run the scripts
   in `analysis/` as described in their module headers.
7. Run `python guards/check_release.py` before publishing or archiving a release.

The committed notebooks have their cell outputs cleared to avoid redistributing data,
runtime metadata, or large binary representations. Random seeds and fixed split files are
provided, but exact GPU results can still vary with hardware and low-level libraries.

## AI-assisted coding disclosure

OpenAI ChatGPT and Codex were used to help draft and debug portions of the analysis code
and to improve documentation. The authors inspected the code, ran the analyses locally,
and checked the reported outputs against source records and numerical consistency checks.
No CUBS image, annotation, or participant-level record was uploaded to these services.
